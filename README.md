# Beget Mail MCP

Beget Mail MCP подключает ящики Beget к MCP-клиентам через Streamable HTTP. Входящая почта читается по IMAP, исходящая отправляется по SMTP.

## Инструменты

- `list_recent_emails` показывает заголовки последних писем.
- `search_emails` ищет по заголовкам и тексту письма, в том числе по фразам с пробелами и кириллицей.
- `get_email` читает письмо по IMAP UID без отметки «прочитано» и возвращает только имена вложений.
- `prepare_email` возвращает предпросмотр с адресатами, темой, текстом и одноразовым токеном.
- `send_email` отправляет письмо с теми же адресатами, темой и текстом по токену предпросмотра.

## Настройки Beget

По официальной справке Beget:

- IMAP: `imap.beget.com`, SSL, порт `993`;
- SMTP: `smtp.beget.com`, SSL, порт `465`;
- логин: полный адрес почтового ящика;
- SMTP-лимиты: до 30 писем в минуту и до 1500 писем в час.

Источник: <https://beget.com/ru/kb/how-to/mail/obshhie-svedeniya>

## Установка и запуск

Скачайте репозиторий и перейдите в его папку:

```text
git clone https://github.com/JKgeneral1/Beget-mail-MCP.git
cd Beget-mail-MCP
```

### Docker Compose

Нужен Docker с Compose 2.30+ и поддержкой Linux-контейнеров. Входящие подключения к контейнеру ограничены локальным интерфейсом хоста. Для работы с почтой хосту нужен исходящий доступ к IMAP и SMTP Beget.

При первом запуске создайте `.env` из шаблона:

```bash
cp .env.example .env
```

В Windows PowerShell используйте `Copy-Item .env.example .env`.

Заполните `.env`, затем запустите или обновите сервис:

```bash
docker compose up -d --build --wait
```

После изменения настроек в `.env` примените их командой `docker compose up -d --force-recreate --wait`.

Compose публикует порт только на `127.0.0.1` и запускает контейнер с лимитами 256 МиБ и 0,25 CPU. В `.env` можно задать `MCP_HOST_PORT`, `MCP_MEMORY_LIMIT` и `MCP_CPU_LIMIT`. Проверка здоровья показывает, отвечает ли сервис. Для проверки почты вызовите `list_recent_emails` с токеном нужного ящика.

### Docker без Compose

```sh
docker build -t beget-mail-mcp .
docker run -d --name beget-mail-mcp --restart unless-stopped --env-file .env -e HOST=0.0.0.0 -e PORT=8000 -p 127.0.0.1:8000:8000 beget-mail-mcp
```

На контейнерной платформе можно собрать образ из того же `Dockerfile`. Передайте настройки через переменные окружения или хранилище секретов платформы, а её HTTPS-вход направьте на порт `8000` контейнера. Для входящих запросов приложение использует порт `PORT`, если платформа задаёт его сама.

### Python

Нужен Python 3.11+. Для Linux и macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
```

Для Windows PowerShell можно использовать интерпретатор из виртуального окружения напрямую:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
```

Заполните `.env`, затем экспортируйте значения удобным для вашей системы способом и запустите:

```bash
HOST=127.0.0.1 PORT=8000 beget-mail-mcp
```

В PowerShell задайте `$env:HOST = '127.0.0.1'` и `$env:PORT = '8000'`, затем выполните `.\.venv\Scripts\beget-mail-mcp.exe`. При запуске через Python передайте переменные из раздела «Настройка ящиков» в окружение процесса.

Проверка состояния без доступа к почте:

```bash
curl http://localhost:8000/health
```

MCP endpoint: `http://localhost:8000/mcp`.

## Настройка ящиков

Задайте список учётных записей в `BEGET_ACCOUNTS_JSON`. Для каждой записи укажите полный адрес, пароль ящика и отдельный токен от 32 символов. Токены можно сгенерировать командой `openssl rand -hex 32`. Храните рабочий `.env` локально.

Пример строки в `.env`:

```dotenv
BEGET_ACCOUNTS_JSON=[{"email":"first@example.com","password":"replace-me","token":"replace-with-unique-token-one-32chars"},{"email":"second@example.com","password":"replace-me","token":"replace-with-unique-token-two-32chars"}]
```

Сгенерируйте отдельный случайный токен для каждого ящика. Один и тот же адрес `/mcp` обслуживает все записи. Токен определяет, какой ящик клиент может читать и с какого адреса может отправлять. Для работы с двумя ящиками добавьте в клиент два подключения с разными токенами. Администратор сервера задаёт записи и перезапускает процесс после изменений.

## Подключение MCP-клиента

Клиенту нужна поддержка Streamable HTTP и заголовка `Authorization: Bearer <токен ящика>`. Для клиента на том же компьютере укажите `http://127.0.0.1:8000/mcp`. Для удалённого клиента используйте доступный ему URL с HTTPS и тем же путём `/mcp`.

При отправке клиент должен показать предпросмотр и запросить подтверждение пользователя перед вызовом `send_email`. Сервер проверяет содержимое письма и токен, а подтверждение человеком обеспечивает клиент.

### Доступ извне по HTTPS

На VPS направьте HTTPS-прокси на опубликованный локальный порт, по умолчанию `http://127.0.0.1:8000`. Если прокси запущен в той же Docker-сети, используйте адрес сервиса `http://beget-mail-mcp:8000`. На управляемой платформе используйте её встроенный HTTPS-вход.

Сохраняйте путь `/mcp` и заголовок `Authorization` при проксировании. В клиенте укажите URL вида `https://mail-mcp.example.com/mcp`. Для каждого ящика настройте отдельное подключение с собственным токеном. Проверка `/health` показывает готовность приложения, а вызов `list_recent_emails` через клиент проверяет доступ к ящику.

Укажите в `MCP_ALLOWED_HOSTS` значения заголовка `Host`, которые HTTPS-вход передаёт приложению, например `mail-mcp.example.com`. Для нескольких значений используйте запятую, а если прокси передаёт порт в заголовке, укажите и его. Значения задаются без схемы и пути.

### Плагин для Codex Desktop

В окне добавления маркетплейса укажите источник `JKgeneral1/Beget-mail-MCP` и Git ref `main`. Поле «Выборочные пути» оставьте пустым. Затем установите **Beget Mail** из добавленного каталога.

Плагин содержит инструкции для работы с почтой. MCP-подключение с URL вашего сервера и токеном ящика добавляется отдельно по инструкции выше. Один и тот же сервер можно использовать и с другими MCP-клиентами.

## Ограничения почтовых операций


По умолчанию сокет IMAP/SMTP ждёт до 15 секунд на операцию ввода-вывода, а сервис выполняет не более двух почтовых операций одновременно. При перегрузке клиент получает сообщение с просьбой повторить попытку. Перед загрузкой письма сервис проверяет его полный размер, включая вложения. Если он превышает 2 МиБ, клиент получает заголовки и причину пропуска тела.

Настройки в `.env`: `BEGET_MAIL_TIMEOUT_SECONDS`, `BEGET_MAX_CONCURRENT_OPERATIONS` и `BEGET_MAX_MESSAGE_BYTES`.

## Безопасность MVP

- секреты читаются только из окружения;
- MCP endpoint закрыт Bearer token;
- соединения с Beget используют TLS;
- письма читаются через `BODY.PEEK`, то есть не помечаются прочитанными;
- адрес отправителя определяется токеном ящика;
- токен предпросмотра действует до 10 минут, принимается один раз и аннулируется при перезапуске процесса;
- тела писем и секреты не журналируются приложением.
